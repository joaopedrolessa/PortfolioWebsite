## Planejamento técnico

Stack prevista: Next.js, TypeScript e Tailwind CSS, com decisões finais durante a implementação. Código modular, tipagem consistente e abstrações somente quando necessárias.

Conteúdo separado dos componentes: TypeScript/JSON para dados estruturados e Markdown ou MDX para estudos de caso, escolhendo a alternativa mais simples. Novos projetos devem usar a mesma estrutura. Preparar organização por idioma sem exigir inglês na V1. Sem CMS, painel administrativo ou banco de dados para gerenciar conteúdo.

Fluxo: editar → revisar → validar → commit/push → deploy automatizado. GitHub Actions para verificações; hospedagem na Vercel. Evitar pipelines duplicados sem benefício.

Repositório público com README sobre objetivo, stack, estrutura, execução local, decisões reais, testes, deploy e melhorias futuras. Link discreto no rodapé ou em Sobre este site. Testar comportamentos relevantes, sem buscar cobertura artificial.

V1 no endereço gratuito da Vercel, preferencialmente `joaopedrolessa.vercel.app`, sujeito à disponibilidade. Não comprar domínio como requisito. Centralizar URL base, metadados, URLs canônicas e SEO. Preparar migração futura e redirecionamentos quando suportados. Verificar HTTPS na publicação.

Analytics: avaliar Vercel Web Analytics primeiro e alternativas gerenciadas como Plausible/Umami se necessário, verificando recursos, custos, privacidade e dados efetivamente coletados. Preferir métricas agregadas sem identificação individual nem infraestrutura própria. V1: visitas, visualizações, origem quando disponível e páginas acessadas. V1.1: eventos de currículo, projetos, GitHub, LinkedIn e e-mail. Avaliar avisos e consentimento conforme implementação; não presumir conformidade automática. As métricas não identificam visitantes como recrutadores nem comprovam contratações.
